# 🛠️ Reporte de Errores: error-watcher

## 📋 Contexto
Basado en las reglas de `.review/0.context_master.md`, se ha analizado el código buscando fallos de ejecución en tiempo real (Runtime), gestión de memoria y robustez.

## 🚨 Hallazgos Críticos

### 1. Fallo Silencioso en Carga de Datos (Data Manager)
**❗ Problema**: En `js/data_manager.js`, el `try/catch` en `init()` y `loadStopData`/`loadCeadData` captura errores pero en algunos casos solo los loguea (`console.error`) sin propagar el estado de error a la UI. Si falla la carga, la UI se queda en "Cargando..." infinitamente o muestra datos vacíos sin feedback al usuario.
**📍 Ubicación**: `js/data_manager.js` (métodos `loadStopData`, `loadCeadData`).
**💥 Escenario de Fallo**:
1. Fallo de red o JSON malformado.
2. `fetch` lanza excepción.
3. `catch` bloquea la excepción, pone `isLoading = false`.
4. Las vistas que dependen de `waiter` (que chequea `isLoaded`) nunca reciben la señal de éxito ni de error explícito y quedan esperando.
**⚠️ Impacto**: Alto. El usuario percibe la aplicación como congelada.
**🛠️ Fix Sugerido**:
```javascript
// js/data_manager.js
async init(codcom = null) {
    // ...
    try {
        await Promise.all([/*...*/]);
        this.state.isLoaded = true;
        // ...
    } catch (error) {
        console.error("❌ DataManager Error:", error);
        this.state.error = error.message; // Store error
        this.state.isLoaded = false; // Ensure it's not marked as loaded
        window.dispatchEvent(new CustomEvent('dataManagerError', { detail: error })); // Notify UI
    } finally {
        this.state.isLoading = false;
    }
}
```

### 2. Acceso Inseguro a Propiedades Profundas (Null Safety)
**❗ Problema**: Múltiples vistas acceden a propiedades profundas de `STATE_DATA` sin validación completa (Optional Chaining inconsistente). Ejemplo: `S.allDataHistory.find(...)` puede retornar `undefined` si no hay datos para la semana, y acceder a `[C.FACTOR_POBLACION]` lanzará error.
**📍 Ubicación**: `vistas2/vista1.html` (Línea 97), `vistas2/vista*.html` (generalizado).
**💥 Escenario de Fallo**:
1. Carga de datos incompleta o semana sin datos históricos.
2. `find()` retorna `undefined`.
3. JS lanza `TypeError: Cannot read properties of undefined`.
4. El script de la vista se detiene y la vista queda a medio renderizar.
**⚠️ Impacto**: Medio. Vistas rotas visualmente.
**🛠️ Fix Sugerido**:
Usar Optional Chaining (`?.`) y Nullish Coalescing (`||`) sistemáticamente.
```javascript
const factorPob = S.allDataHistory.find(r => r[C.ID_SEMANA] === S.currentSemana)?.[C.FACTOR_POBLACION] || 1;
```

### 3. Race Condition en IA Module (IA2)
**❗ Problema**: `js/ia2.js` lanza `fetchAllAnalyses` al detectar `dataManagerLoaded`. Si el usuario navega rápidamente entre vistas o recarga, podrían dispararse múltiples peticiones si `this.fetching` no se gestiona con precisión atómica (aunque tiene un flag, la condiciones de carrera en navegadores lentos o con `localStorage` lento son posibles). Además, `localStorage` puede lanzar excepción si está lleno (QuotaExceededError), lo cual no está manejado explícitamente en `saveCache`.
**📍 Ubicación**: `js/ia2.js`.
**💥 Escenario de Fallo**:
1. `localStorage` lleno (común en apps con muchos datos cacheados).
2. `setItem` lanza excepción.
3. El update de la vista se interrumpe si no está dentro de un try/catch específico para el storage.
**⚠️ Impacto**: Bajo/Medio. Pérdida de funcionalidad de IA.
**🛠️ Fix Sugerido**:
```javascript
saveCache(data) {
    try {
        // ... setItem ...
    } catch (e) {
        console.warn('IA Cache Full/Error:', e);
        // Opcional: Limpiar cache antigua
    }
}
```

### 4. Z-Score Fallback en Vistas
**❗ Problema**: En `vista19.html` y `vista20.html`, se confía en que `z_score` exista. Aunque se añadió `|| 0` recientemente, la lógica de ordenamiento `sort((a, b) => ...)` podría tener comportamientos inesperados si todos son 0.
**📍 Ubicación**: `vistas2/vista19.html`, `vistas2/vista20.html`.
**💥 Escenario de Fallo**: Datos CEAD no procesados correctamente (sin columna z_score). Todos los valores son 0. El UI muestra una lista vacía o arbitraria sin indicar que "No hay datos significativos".
**⚠️ Impacto**: Bajo. Información visual engañosa (no error de consola).
**🛠️ Fix Sugerido**: Validar si hay datos con Z-Score significativo antes de renderizar la tabla/lista.

## 📉 Recomendaciones Generales
1.  **Implementar Global Error Boundary**: Un manejador de eventos `window.onerror` o `unhandledrejection` que muestre un "Toast" de error al usuario en lugar de fallar silenciosamente.
2.  **Validar Integridad de Datos**: Al cargar el JSON, verificar que las columnas críticas (`C.Z_SCORE`, `C.MEDIA_MOVIL_4S`) existan en el primer registro. Si no, lanzar alerta "Datos Incompatibles".
