# 🛠️ REPORTE DE ERRORES (Runtime Reliability)

**❗ Problema**: Acceso inseguro al DOM sin validación de existencia de elementos.
**📍 Ubicación**: `js/utils/ui-helper.js` / Líneas 22-23, 64-70.
**💥 Escenario de Fallo**: Si una vista (HTML) no contiene exactamente los IDs esperados por el helper (ej. `v1_casos`), el script fallará silenciosamente si no hay guardas, o lanzará error si se intenta acceder a propiedades de `null`. Aunque `renderKpi` tiene guardas, `setText` y `setHtml` son puntos de falla potenciales si se usan masivamente.
**⚠️ Impacto**: Medio (Puede romper la ejecución de scripts posteriores en la vista).
**🛠️ Fix Sugerido**: Implementar guardas consistentes en todos los setters del `UIHelper`.

---

**❗ Problema**: Riesgo de Carrera (Race Condition) en inicialización de datos.
**📍 Ubicación**: `js/data_manager.js` / método `init()`.
**💥 Escenario de Fallo**: Si se invoca `DataManager.init()` múltiples veces rápidamente (ej. clics rápidos en navegación), la guarda `if (this.state.isLoading) return;` evita la segunda carga, pero el receptor del evento `dataManagerLoaded` podría recibir un estado parcial si el primero falla y no resetea `isLoading` correctamente en todos los flujos de error.
**⚠️ Impacto**: Alto (Inconsistencia en los datos mostrados en el dashboard).
**🛠️ Fix Sugerido**: Asegurar el reseteo de `state.isLoading = false` en el bloque `finally` del método `init`.

---

**❗ Problema**: Comparación débil de tipos en lógica de recuperación histórica.
**📍 Ubicación**: `vistas2/vista14.html` / Línea 154: `r[C.ANIO] == (totalRow[C.ANIO] - 1)`.
**💥 Escenario de Fallo**: Si el dato del CSV se parsea involuntariamente como string en una columna y número en otra, la comparación podría ser errática.
**⚠️ Impacto**: Bajo (Riesgo de bugs de "lógica silenciosa").
**🛠️ Fix Sugerido**: Utilizar comparación estricta `===` previa conversión explícita a `Number()`.
