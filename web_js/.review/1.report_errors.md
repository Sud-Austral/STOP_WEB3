# 🛠️ Reporte de Errores Runtime (Agente: error-watcher)

## 📋 Resumen
Análisis enfocado en robustez de ejecución, manejo de asincronía y seguridad de tipos en el entorno Vanilla JS.

## 🚨 Hallazgos Críticos

**❗ Problema**: Polling Infinito en Carga de Vistas
**📍 Ubicación**: `index_vistas2.html` (y scripts de vistas como `vista1.html`), Función `waitForData`
**💥 Escenario de Fallo**: Si `js/data_manager.js` falla al cargar los datos (`isLoaded` nunca es true due to fetch error), las vistas se quedan en un bucle infinito de `setTimeout` consumiendo CPU y pila de llamadas, sin mostrar error al usuario.
**⚠️ Impacto**: Alto (Bloqueo de UI / "Hanging")
**🛠️ Fix Sugerido**:
```javascript
const waitForData = (attempts = 0) => {
    return new Promise((resolve, reject) => {
        const check = () => {
             // Timeout tras 10s (100 * 100ms)
            if (attempts > 100) return reject("Timeout loading data");
            if (window.STATE_DATA && window.STATE_DATA.isLoaded) resolve();
            else { attempts++; setTimeout(check, 100); }
        };
        check();
    });
};
```

**❗ Problema**: Race Condition en Navegación Rápida
**📍 Ubicación**: `index_vistas2.html`, Función `App.loadView`
**💥 Escenario de Fallo**: Si el usuario hace clic rápidamente en "Siguiente" varias veces, se disparan múltiples `fetch` de vistas. No hay mecanismo de cancelación (`AbortController`). Las vistas pueden resolverse en desorden, mostrando una vista incorrecta o mezclando estado si `executeViewScript` se ejecuta sobre un contenedor ya modificado.
**⚠️ Impacto**: Medio (UI inconsistente)
**🛠️ Fix Sugerido**: Implementar un `currentFetchController` con `AbortController` al iniciar `loadView` para cancelar peticiones pendientes de vistas anteriores.

**❗ Problema**: Fallback de Predicción Potencialmente Inestable
**📍 Ubicación**: `notebook/proceso_cead.py`, Función `predecir_sarima_secuencial`
**💥 Escenario de Fallo**: Aunque se agregó un sanity check, si `avg_base` es 0 (por datos vacíos), la división o lógica posterior podría fallar o producir valores NaN que rompen `JSON.stringify` o causan errores en el frontend al parsear `null`.
**⚠️ Impacto**: Alto (Integridad de Datos)
**🛠️ Fix Sugerido**: Asegurar que `fallback_val` nunca sea `NaN` o `Infinite`.
```python
if np.isnan(fallback_val) or np.isinf(fallback_val): fallback_val = 0
```

**❗ Problema**: Acceso a Propiedades en `undefined` durante Rendering
**📍 Ubicación**: `vistas2/*.html` (Generalizado)
**💥 Escenario de Fallo**: Al acceder a `row[C.CASOS_ACTUAL]` dentro de un `map` o `find`, si `row` es `undefined` (datos faltan para esa semana), lanza `TypeError: Cannot read properties of undefined`. Aunque se usa `?.` en algunos lugares, no es consistente en todos los maps.
**⚠️ Impacto**: Medio (Rompe el renderizado del gráfico completo)
**🛠️ Fix Sugerido**: Usar siempre Optional Chaining y Nullish Coalescing: `r?.[C.CASOS_ACTUAL] ?? 0`.

## 📉 Errores Menores

**❗ Problema**: Comparación Abstracta (`==`) en Filtrado
**📍 Ubicación**: `js/data_manager.js` (detectado en lógica general)
**💥 Escenario de Fallo**: Posibles errores si `id_semana` viene como string del JSON y se compara con number sin conversión explícita.
**⚠️ Impacto**: Bajo
**🛠️ Fix Sugerido**: Usar `===` y asegurar tipos (parseInt) al cargar datos.
