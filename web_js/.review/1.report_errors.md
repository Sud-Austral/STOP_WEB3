# 🛠️ Reporte de Errores: error-watcher

## 📋 Contexto
Revisión de Robustez y Runtime (Vanilla JS).
Fecha: 2026-02-16

## 🚨 Hallazgos Críticos

### 1. Incoherencia en Manejo de Errores (Fix Parcial)
**❗ Problema**: Se implementó `dataManagerError` en `DataManager.init`, pero los métodos subyacentes `loadStopData` y `loadCeadData` (si existen) podrían tener sus propios bloques `try/catch` que silencien el error antes de que llegue al bloque principal.
**📍 Ubicación**: `js/data_manager.js` (Métodos de carga individual).
**💥 Escenario de Fallo**: `fetch` falla dentro de `loadStopData`. Su `catch` imprime en consola y retorna `null` o `undefined`. `Promise.all` en `init` recibe ese valor "exitosamente" (no rechaza) y el flujo continúa con datos corruptos, evadiendo el Manejador Global de Errores.
**⚠️ Impacto**: Alto. UI rota sin pantalla de error.
**🛠️ Fix Sugerido**: Asegurar que los métodos de carga **lancen** (re-throw) el error.
```javascript
async loadStopData() {
    try { ... } catch(e) { throw e; } // O no usar try/catch aquí.
}
```

### 2. Race Condition en `IA2` vs `UI`
**❗ Problema**: `js/ia2.js` inyecta contenido en elementos `v{i}_ia_analysis`. Si el usuario cambia de vista rápidamente (Single Page Navigation en `app.js`), el elemento DOM de la vista anterior puede ya no existir cuando la IA responde, o peor, la respuesta de la IA de la vista 1 se intenta escribir en el DOM de la vista 2 (si se reutilizan IDs o contenedores, aunque aquí parece haber IDs únicos).
Riesgo mayor: `updateAllViews` intenta actualizar 25 vistas, pero solo 1 está visible/en el DOM si la navegación destruye las otras (MPA vs SPA).
**📍 Ubicación**: `js/ia2.js` (Línea 109).
**💥 Escenario de Fallo**:
1. Usuario carga Vista 1. IA empieza fetch.
2. Usuario va a Vista 2. Vista 1 se desmonta del DOM.
3. IA responde y llama `document.getElementById('v1_ia_analysis')`.
4. Retorna `null`. No hay error grave (hay chequeo `if (el)`), pero si la lógica asume que "si ya cargué datos, muéstralos", al volver a Vista 1, puede que no se refresque automáticamente si confía solo en el evento `dataManagerLoaded` inicial.
**⚠️ Impacto**: Medio. Análisis IA no aparece al navegar.
**🛠️ Fix Sugerido**: Llama a `IAModuleV2.updateAllViews()` cada vez que se carga una vista nueva (`App.loadView`).

### 3. Fuga de Memoria en `setInterval` / Listeners
**❗ Problema**: Si alguna vista usa `setInterval` para animaciones o polling, y no se limpia al cambiar de vista (`app.js` hace `innerHTML = ...`), los intervalos siguen corriendo en background, consumiendo CPU y generando errores al intentar tocar DOM inexistente.
**📍 Ubicación**: `vistas2/*.html` (Revisar scripts embebidos).
**⚠️ Impacto**: Medio (Degradación de performance con el tiempo).
**🛠️ Fix Sugerido**: Implementar un registro central de intervalos `App.intervals.push(id)` y limpiarlos en `App.loadView` antes de renderizar la nueva.

## 📉 Recomendaciones
1.  **Auditoría de Re-throw**: Verificar que `loadStopData` no se trague las excepciones.
2.  **Lifecycle Hook**: Agregar `onViewUnload` en `App` para limpieza.
