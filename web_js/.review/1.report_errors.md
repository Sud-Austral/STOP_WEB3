## 🔴 CRÍTICOS

### ERR-001: `Promise.all` Fail-Fast sin Fallback Granular
**❗ Problema**: `DataManager.init()` ejecuta `Promise.all([loadStopData, loadCeadData, loadClusterConfig, loadComunasData])`. Si **cualquier** loader falla (ej: CEAD no disponible), **todos los datos se pierden** y el estado queda `isLoaded: false`. Las vistas nunca renderizan.

**📍 Ubicación**: `js/data_manager.js:81-86`

**💥 Escenario de Fallo**:
1. Usuario abre la app con `?codcom=13101`.
2. Servidor de CEAD está caído (404/500).
3. `Promise.all` rechaza inmediatamente.
4. `STATE_DATA.isLoaded` permanece `false`.
5. Todas las vistas quedan en spinner infinito ("Cargando...").

**⚠️ Impacto**: **Crítico** — La app queda completamente inutilizable por un fallo en una sola fuente.

**🛠️ Fix Sugerido**:
```javascript
// Reemplazar Promise.all con Promise.allSettled
const results = await Promise.allSettled([
    this.loadStopData(this.state.comunaId),
    this.loadCeadData(this.state.comunaId),
    this.loadClusterConfig(),
    this.loadComunasData()
]);

results.forEach((result, i) => {
    if (result.status === 'rejected') {
        const sources = ['STOP', 'CEAD', 'Cluster', 'Comunas'];
        console.warn(`⚠️ DataManager: ${sources[i]} falló:`, result.reason);
    }
});

// Marcar como cargado si al menos STOP o CEAD tuvo éxito
this.state.isLoaded = results[0].status === 'fulfilled' || results[1].status === 'fulfilled';
```

### ERR-002: Busy-Wait Infinito en Vistas (`waitForData`)
**❗ Problema**: Cada vista implementa un polling `setTimeout` esperando `STATE_DATA.isLoaded`. Si `DataManager` falla (ERR-001), este loop **nunca termina**. No hay timeout de seguridad en la mayoría de las vistas.

**📍 Ubicación**: `vistas2/vista1.html` a `vistas2/vista27.html` (patrón repetido ~27 veces)

**💥 Escenario de Fallo**:
1. `DataManager.init()` falla por red.
2. `STATE_DATA.isLoaded` queda `false`.
3. Cada vista ejecuta `setTimeout(check, 100)` indefinidamente.
4. Se acumulan 27 * 10/seg = 270 invocaciones/seg de funciones de polling.
5. CPU se dispara, la pestaña se vuelve irresponsable.

**⚠️ Impacto**: **Crítico** — Memory leak progresivo + CPU thrashing.

**🛠️ Fix Sugerido**:
```javascript
// Patrón centralizado con timeout (en utils/waiter.js)
function waitForData(timeoutMs = 15000) {
    return new Promise((resolve, reject) => {
        const start = Date.now();
        const check = () => {
            if (window.STATE_DATA?.isLoaded) return resolve();
            if (Date.now() - start > timeoutMs) return reject(new Error('Data timeout'));
            setTimeout(check, 200);
        };
        check();
    });
}
```

## 🟠 ALTOS

### ERR-003: `getInterpretation()` Busy-Wait sin Límite
**❗ Problema**: `IAModule.getInterpretation()` contiene un `while(this.isLoading)` con `await setTimeout(100)`. Si la API nunca responde (timeout de red sin límite en `fetch`), este loop **bloquea indefinidamente** el hilo de ejecución de la vista.

**📍 Ubicación**: `js/ia.js:493-495`

**💥 Escenario de Fallo**:
1. Vista llama `IAModule.getInterpretation('vista1')`.
2. La API de BigModel está lenta (>60s).
3. `isLoading` permanece `true`.
4. `while(this.isLoading)` ejecuta infinitamente.
5. La vista nunca termina de renderizar el texto IA.

**⚠️ Impacto**: **Alto** — UX degradada, recurso retenido.

**🛠️ Fix Sugerido**:
```javascript
async getInterpretation(viewId) {
    if (!this.isLoaded && !this.isLoading) {
        await this.generateAllInterpretations();
    }
    // Timeout de seguridad: 30 segundos máximo
    let waited = 0;
    while (this.isLoading && waited < 30000) {
        await new Promise(resolve => setTimeout(resolve, 200));
        waited += 200;
    }
    return this.interpretations[viewId] || this.getDefaultInterpretations()[viewId];
}
```

### ERR-004: `fetch` sin `AbortController` / Timeout
**❗ Problema**: Las llamadas `fetch` en `DataManager` (`loadStopData`, `loadCeadData`) y `IAModule` (`generateAllInterpretations`) no implementan timeout. En redes lentas o servidores caídos, el `fetch` puede quedar pendiente indefinidamente.

**📍 Ubicación**: `js/data_manager.js:237-293`, `js/data_manager.js:295-342`, `js/ia.js:295-302`

**💥 Escenario de Fallo**: Red inestable → fetch pendiente → app congelada.

**⚠️ Impacto**: **Alto**

**🛠️ Fix Sugerido**:
```javascript
async loadStopData(id) {
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 15000); // 15s
    try {
        const response = await fetch(url, { signal: controller.signal });
        // ...
    } finally {
        clearTimeout(timeoutId);
    }
}
```

### ERR-005: `executeScripts()` Re-crea `<script>` sin Cleanup
**❗ Problema**: `App.executeScripts()` itera `<script>` tags del HTML cargado, crea nuevos `<script>` elements y los appenda al DOM. Los scripts anteriores (de la vista previa) no se limpian. Variables globales definidas en IIFEs previas persisten.

**📍 Ubicación**: `js/app.js:315-329`

**💥 Escenario de Fallo**:
1. Navegar de `vista5` a `vista6` a `vista5`.
2. El IIFE de `vista5` se ejecuta dos veces.
3. Se crean Chart.js instances duplicados en el mismo canvas.
4. Memory leak progresivo por `Chart` instances huérfanos.

**⚠️ Impacto**: **Alto** — Confirmado parcialmente mitigado por `destroyAllCharts()`, pero no cubre listeners ni variables globales de vista.

**🛠️ Fix Sugerido**: `destroyAllCharts()` es correcto pero insuficiente. Añadir un mecanismo de cleanup por vista (ej: `window._currentVistaCleanup`).

---

### ERR-006: `JSON.parse` de Respuesta IA Truncada — Fix Heurístico Frágil
**❗ Problema**: El parser de respuestas IA (`parseAIResponse`) intenta "arreglar" JSON truncado cortando en la última comilla y cerrando con `}`. Este heurístico puede generar JSON válido pero con valores incorrectos (texto cortado a mitad de frase).

**📍 Ubicación**: `js/ia.js:406-434`

**💥 Escenario de Fallo**:
1. API retorna JSON cortado: `{"vista1": "Análisis del d`
2. El fix heurístico genera: `{"vista1": "Análisis del d"}`
3. El usuario ve texto sin sentido en el dashboard.

**⚠️ Impacto**: **Alto** — Datos incorrectos mostrados al usuario como análisis IA.

**🛠️ Fix Sugerido**: Solicitar streaming JSON o validar que cada valor tenga al menos 20 caracteres. Marcar interpretaciones truncadas con un flag visual.

## 🟡 MEDIOS

### ERR-007: Null Safety en `document.getElementById` de Vistas
**❗ Problema**: Múltiples vistas acceden a elementos DOM sin validar existencia. Si el HTML cambia o un ID es renombrado, se produce `TypeError: Cannot set properties of null`.

**📍 Ubicación**: `vistas2/vista16.html:231-235`, `vistas2/vista3.html:197`, `vistas2/vista5.html:168` (patrón generalizado)

**⚠️ Impacto**: **Medio** — La vista específica falla silenciosamente.

**🛠️ Fix Sugerido**:
```javascript
const el = document.getElementById('v16_rank_nac');
if (el) el.textContent = miData.ranking_nacional_semanal_tasa || '--';
```

### ERR-008: `Math.max(...array)` con Arrays Grandes
**❗ Problema**: Se usa `Math.max(...semanaIds)` con arrays potencialmente de miles de elementos. El spread operator tiene un límite de argumentos (~65K en V8). Con comunas con historial extenso, puede lanzar `RangeError: Maximum call stack size exceeded`.

**📍 Ubicación**: `js/ia.js:162`, `vistas2/vista16.html` (normalización de tasas/ranks)

**⚠️ Impacto**: **Medio**

**🛠️ Fix Sugerido**:
```javascript
const maxSemana = semanaIds.reduce((a, b) => Math.max(a, b), -Infinity);
```

### ERR-009: `localStorage.setItem` sin Manejo de `QuotaExceededError`
**❗ Problema**: `IAModule.saveToCache()` tiene `try/catch` genérico pero no distingue `QuotaExceededError`. Si el storage está lleno, el cache no se guarda y el usuario re-genera la interpretación IA en cada carga.

**📍 Ubicación**: `js/ia.js:87-98`

**⚠️ Impacto**: **Medio** — Llamadas API innecesarias, potencial rate limiting.

**🛠️ Fix Sugerido**: En el `catch`, intentar `cleanOldCaches()` y reintentar una vez.

---

### ERR-010: Tipo String en `trendDataViolento` / `trendDataPropiedad`
**❗ Problema**: En `vista18.html`, `toFixed(1)` retorna un string. Los datasets de Chart.js reciben strings `"45.2"` en lugar de números `45.2`. Chart.js los castea, pero el plugin `datalabels` puede comportarse inconsistentemente.

**📍 Ubicación**: `vistas2/vista18.html` (cálculo de trendDataViolento/Propiedad)

**⚠️ Impacto**: **Medio**

**🛠️ Fix Sugerido**: `return t > 0 ? parseFloat((v / t * 100).toFixed(1)) : 0;`

---

### ERR-011: Race Condition entre `IAModuleV2.init()` y `DataManager`
**❗ Problema**: `IAModuleV2.init()` se ejecuta inmediatamente al cargar el script (línea 263: `window.IAModuleV2.init()`). En ese momento, `STATE_DATA` puede no estar cargado aún. El módulo intenta acceder a `window.STATE_DATA.codcom` que puede ser el valor default (13101) en lugar del real.

**📍 Ubicación**: `js/ia2.js:22-38, 263`

**⚠️ Impacto**: **Medio** — Cache key incorrecta, interpretaciones de comuna equivocada.

**🛠️ Fix Sugerido**: Diferir `init()` hasta el evento `dataManagerLoaded`.
