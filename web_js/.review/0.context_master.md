# 📘 CONTEXTO MAESTRO: STOP WEB 3 (RID SIMULATOR)

## 📋 METADATA
- **Fecha**: 2026-02-16
- **Stack**: Vanilla JS (ES2020+), CSS (Tailwind Colors), Python (ETL)
- **Browser Support**: Modern Browsers (Chrome 80+, Edge Chromium, Firefox, Safari). No IE11 support (uses Promises, arrow functions, async/await).
- **Criticidad**: ALTA. Dashboard de inteligencia para toma de decisiones de seguridad pública.
- **Tipo de Proyecto**: Client-side Dashboard (SPA-like) con procesamiento de datos estáticos JSON pre-calculados.

## 🎯 OBJETIVOS DE NEGOCIO
Proveer una herramienta de visualización ("RID Simulator") que consolida datos de denuncias (STOP - Carabineros) y análisis delictual (CEAD - SPD). Objetivos clave:
1.  **Visualización Estratégica**: Transformar datos crudos en KPIs, tendencias y proyecciones (SARIMA).
2.  **Inteligencia Artificial**: Generar análisis automáticos de texto para cada vista (Integración GLM-4).
3.  **Portabilidad**: Funcionar sin backend activo, consumiendo solo archivos estáticos, para fácil distribución o deployment en entornos restringidos.
4.  **Exportación**: Generar reportes PDF de alta calidad para informes oficiales.

## 🏗️ ARQUITECTURA TÉCNICA
- **Patrón**: **Global Namespace / Module Mix**.
    - Transición a `window.RID` (Namespace centralizado).
    - Legado: `window.STATE_DATA`, `window.DataManager`.
- **Flujo de Datos**:
    1.  **Python ETL**: `notebook/proceso.py` y `proceso_cead.py` procesan Excel/CSV -> generan JSONs estáticos.
    2.  **JS DataManager**: Carga y unifica JSONs en memoria (`RID.State` / `STATE_DATA`).
    3.  **Vistas (HTML/JS)**: Renderizado directo al DOM (`vistas2/vistaX.html`) usando datos globales.
    4.  **IA**: `js/ia2.js` consume API externa y cachea en `localStorage`.
- **Web Standards Compliance**: Alto. Uso de `fetch`, `CustomEvent`, `Intl.NumberFormat`, `localStorage`.
- **Restricciones de Entorno**:
    - **No Backend**: Todo el cálculo dinámico y renderizado es client-side.
    - **Performance**: Renderizado de 25+ gráficos Chart.js simultáneos o en secuencia.
    - **Seguridad**: Claves de API en cliente (Ofuscadas, riesgo conocido).

## ⚠️ RESTRICCIONES Y ÁREAS SENSIBLES
- **Punto Crítico de Datos**: `js/data_manager.js` maneja la integridad de la carga. Fallos aquí detienen toda la app.
- **Estructura de Vistas**: `vistas2/vista*.html`. Cada archivo es una "página" parcial. Cambios en la estructura base (`template.html`) requieren réplica manual en 25 archivos (Mitigación: `UIHelper`).
- **Scripts de Configuración**: `js/config/columns.js` y `js/data.js` definen el mapeo de columnas. Desincronización con Python rompe la app.
- **Seguridad**: `js/ia2.js` contiene lógica de acceso a API paga.

---
### Resumen Ejecutivo
Proyecto robusto en funcionalidad pero con deuda técnica en mantenibilidad (código repetido en vistas) y seguridad (credenciales en frontend). La arquitectura basada en archivos estáticos es eficiente para distribuirse pero limita la protección de secretos. La reciente introducción de `RID` namespace y `UIHelper` marca una mejora significativa en la calidad del código base.

## ⚠️ REQUISITO CRÍTICO DE NEGOCIO
- **INTEGRIDAD DE DATOS**: Es imperativo mostrar **SOLO DATOS REALES** en la interfaz web.
- **PROHIBIDO EL MOCKING**: Bajo ninguna circunstancia se deben utilizar datos simulados, aleatorios o "hardcodeados" para rellenar gráficos o tablas en las vistas de producción (`vistas2/`).
- **MANEJO DE FALTA DE DATOS**: Si los datos reales no están disponibles, la interfaz debe mostrar explícitamente un estado de "Cargando...", "Sin Datos", o "En Desarrollo", en lugar de inventar valores. La confianza del usuario en la herramienta depende de la veracidad absoluta de la información mostrada.
