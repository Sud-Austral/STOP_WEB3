# 🔍 Reporte de Calidad de Código (Agente: code-reviewer)

## 📋 Resumen
Evaluación de mantenibilidad y rendimiento (LCP/INP) en Vanilla JS.

## 💡 Hallazgos Críticos

**💡 Hallazgo**: Duplicación Masiva de Lógica de Inicialización (`waitForData`)
**🏗️ Principio/Métrica**: Violación DRY (Don't Repeat Yourself)
**📍 Ubicación**: Todos los archivos `vistas2/*.html` (Ej: `vista1.html`, Lín 75-83)
**🛠️ Refactor Sugerido**: Mover `waitForData` a `js/utils.js` o `js/data_manager.js` y exponerlo globalmente (`App.waitForData()`).
**📈 Beneficio**: Reduce ~10 líneas por archivo (x30 vistas = 300 líneas menos) y centraliza el manejo de timeouts.

**💡 Hallazgo**: Uso Excesivo de `.innerHTML` para Renderizado
**🏗️ Principio/Métrica**: Layout Thrashing & Rendimiento de Renderizado
**📍 Ubicación**: `index_vistas2.html`, Función `loadView`
**🛠️ Refactor Sugerido**: Aunque cómodo, destruir y recrear todo el DOM es costoso. Si la estructura base es similar, actualizar solo contenidos (`textContent`) o usar `DocumentFragment`.
**📈 Beneficio**: Menor carga de CPU y menos parpadeos visuales (Mejor INP).

**💡 Hallazgo**: Dependencia Global (`window.STATE_DATA`, `window.COLS`)
**🏗️ Principio/Métrica**: Inversión de Dependencia / Modularidad
**📍 Ubicación**: `js/data_manager.js` y todas las vistas
**🛠️ Refactor Sugerido**: Encapsular el acceso a datos en un API (`DataManager.getStopData()`, `DataManager.getCeadData()`) en lugar de acceder a propiedades crudas globales.
**📈 Beneficio**: Facilita el refactor interno de la estructura de datos sin romper las vistas.

**💡 Hallazgo**: Funciones Anónimas Autoejecutables (IIFE) Gigantes
**🏗️ Principio/Métrica**: Testabilidad y Legibilidad
**📍 Ubicación**: `vistas2/*.html` (Ej: `(async function initVista1_V2() {...})()`)
**🛠️ Refactor Sugerido**: Extraer la lógica de renderizado a una función nombrada `renderVista1(container)` que se pueda invocar/testear independientemente.
**📈 Beneficio**: Mejora la trazabilidad de errores en el stack trace.

## 📉 Errores Menores

**💡 Hallazgo**: Hardcoding de IDs de Semanas en Cálculos
**🏗️ Principio/Métrica**: Fragilidad
**📍 Ubicación**: `vistas2/vista1.html` y otras (`last8.map(id => S.getDateLabel(id))`)
**🛠️ Refactor Sugerido**: Usar constantes o configuración para definir "últimas 8 semanas" en lugar de `slice(0, 8)` hardcodeado repetidamente.

**💡 Hallazgo**: API Key Ofuscada Insegura
**🏗️ Principio/Métrica**: Seguridad por Oscuridad
**📍 Ubicación**: `js/ia.js`, `getKey`
**🛠️ Refactor Sugerido**: Mover la lógica de autenticación al backend. El cliente nunca debería tener acceso a la función de descifrado completa.
