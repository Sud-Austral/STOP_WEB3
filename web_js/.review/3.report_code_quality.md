# 🛠️ Reporte de Code Quality: code-reviewer

## 📋 Contexto
Revisión de calidad y performance web basada en `.review/0.context_master.md` y mejores prácticas de Vanilla JS.

## 🔎 Code Smells

### 1. Global State Pollution (P0)
**💡 Hallazgo**: Uso extensivo de `window.` para exponer módulos críticos e instanciarlos (`window.STATE_DATA`, `window.COLS`, `window.App`, `window.IAModule`). Esto crea dependencias implícitas, riesgos de colisión con librerías de terceros y dificulta el testing unitario y la refactorización modular.
**🏗️ Principio/Métrica**: **Namespace pollution / Module Pattern**.
**📍 Ubicación**: `js/data.js` (Línea 24), `js/ia2.js` (Línea 5), `js/data_manager.js` (Línea 6).
**🛠️ Refactor Sugerido**: Usar un módulo global único (`RIDApp.Data`, `RIDApp.IA`) o transicionar a ECMAScript Modules (`import` / `export`) en el core JS si el target browser lo permite.
**📈 Beneficio**: Mantenibilidad, Testability, Evitar conflictos.

### 2. DOM Access Inside Loops / Views (P1)
**💡 Hallazgo**: En `vistas2/*.html`, el acceso al DOM ocurre dinámicamente cada vez que se carga la vista, usando `document.querySelectorAll()` o `document.getElementById` repetidamente para elementos estáticos (`.comuna-fill`, `.semana-fill`). En `ia2.js`, el `updateAllViews()` busca TODOS los elementos a la vez en un bucle (`document.getElementById(v{i}_ia_analysis`).
**🏗️ Principio/Métrica**: **Layout Thrashing / DOM Access**.
**📍 Ubicación**: `js/ia2.js` (Línea 109: Update loop), `vistas2/vista1.html` (Línea 90).
**🛠️ Refactor Sugerido**: Cachear las referencias DOM en la inicialización o usar un helper `DOMCache` que mapee IDs a nodos una sola vez. En `updateAllViews` de IA, usar `requestAnimationFrame` para agrupar las escrituras DOM si son masivas.
**📈 Beneficio**: Performance (INP - Interaction to Next Paint). Reducción de overhead.

### 3. Duplicate Logic (DRY Violation) (P2)
**💡 Hallazgo**: La lógica de formateo de KPIs (flechas arriba/abajo, colores rojo/verde) se repite `n` veces en `vistas2/*.html` (`vista1`, `vista2`, etc.). Si se cambia el diseño visual de "subida positiva" vs "subida negativa", habría que editar 25 archivos.
**🏗️ Principio/Métrica**: **DRY (Don't Repeat Yourself)**.
**📍 Ubicación**: `vistas2/*.html` (Bloques `<script>` embebidos).
**🛠️ Refactor Sugerido**: Extraer lógica de presentación a `js/utils/ui-helper.js` (ej: `UI.renderKPI(element, value, delta, config)`).
**📈 Beneficio**: Mantenibilidad extrema. Cambios visuales centralizados.

### 4. Magic Numbers & Hardcoded Strings (P2)
**💡 Hallazgo**: Uso de constantes hardcodeadas dispersas: IDs de vistas (`vista1`..`vista25`), claves de `localStorage` (`ia_analysis_v2_`), rutas relativas (`data/cead_split`).
**🏗️ Principio/Métrica**: **Configurability**.
**📍 Ubicación**: `js/ia2.js` (Línea 7, 107), `js/data_manager.js` (Línea 9).
**🛠️ Refactor Sugerido**: Centralizar configuración en `js/config/app-config.js` y exportar constantes (`AppConfig.VIEWS`, `AppConfig.PATHS`).
**📈 Beneficio**: Facilidad de cambio de entorno (Dev/Prod), reducción de errores tipográficos.

## 📉 Recomendaciones de Performance (LCP/CLS)
1.  **Lazy Load**: Las librerías pesadas (`html2canvas`, `jspdf`) se cargan siempre al inicio (`defer`). Deberían cargarse dinámicamente (`import()`) solo al pulsar "Exportar PDF".
2.  **Resource Prioritization**: `vistas2/*.html` carga sus scripts embebidos al insertarse en el DOM. Esto puede bloquear el hilo principal. Considerar `Web Workers` para cálculos pesados (si hubieran) o `requestIdleCallback` para actualizaciones de UI no críticas (como el badge de IA).
