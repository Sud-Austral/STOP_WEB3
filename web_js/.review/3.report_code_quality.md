## 🏗️ ARQUITECTURA Y MANTENIBILIDAD

### CQ-001: `waitForData()` Duplicado ×27
**💡 Hallazgo**: Cada vista en `vistas2/` implementa su propia versión del patrón de espera, con variaciones menores (timeout, intervalo, condición). Esto viola DRY masivamente.

**🏗️ Principio**: DRY

**📍 Ubicación**: `vistas2/vista1.html` a `vistas2/vista27.html`

**🛠️ Refactor Sugerido**:
```javascript
// js/utils/waiter.js (centralizado)
window.waitForSTOP = (timeoutMs = 15000) => new Promise((resolve, reject) => {
    const t0 = Date.now();
    const poll = () => {
        if (window.STATE_DATA?.isLoaded) return resolve(window.STATE_DATA);
        if (Date.now() - t0 > timeoutMs) return reject(new Error('STOP data timeout'));
        setTimeout(poll, 200);
    };
    poll();
});

// En cada vista:
const S = await waitForSTOP();
```

**📈 Beneficio**: Mantenibilidad (un solo punto de cambio), Robustez (timeout garantizado).

### CQ-003: Global Scope Pollution (8+ Objetos en `window`)
**💡 Hallazgo**: Se exponen directamente en `window`:
- `STATE_DATA`, `STATE_DATA_CEAD`, `COLS`, `COLS_CEAD`
- `DataManager`, `App`, `IAModule`, `IAModuleV2`
- `PDFModule`, `COMUNAS_DATA`, `RID`

`rid-core.js` declara `window.RID` como namespace pero ningún módulo lo usa.

**🏗️ Principio**: Encapsulation / Module Pattern

**📍 Ubicación**: `js/rid-core.js`, `js/data.js`, `js/app.js`, etc.

**🛠️ Refactor Sugerido**: Migrar progresivamente a ESM (`import/export`) o al menos agrupar bajo `window.RID`:
```javascript
window.RID.State = STATE_DATA;
window.RID.DataManager = DataManager;
window.RID.IA = IAModule;
```

**📈 Beneficio**: Namespace limpio, evita colisiones, facilita testing.

### CQ-004: Vistas como HTML Strings con JS Inline
**💡 Hallazgo**: Cada vista es un archivo `.html` con CSS `<style>` inline y un `<script>` IIFE autocontenido. No hay separación HTML/JS/CSS. Esto impide:
- Linting del JS de vistas
- Tree-shaking de funciones comunes
- Testing unitario de la lógica de vistas

**🏗️ Principio**: Separation of Concerns

**📍 Ubicación**: `vistas2/*.html` (27 archivos)

**🛠️ Refactor Sugerido** (incremental):
1. Extraer el `<script>` de cada vista a `vistas2/js/vistaX.js`.
2. En el HTML, referenciar `<script src="vistas2/js/vistaX.js"></script>`.
3. Esto permite lint, minificación, y testing individual.

**📈 Beneficio**: Calidad de código, desarrollo, testing.

### CQ-005: `dispatchLegacyEvents()` — God Adapter (125 líneas)
**💡 Hallazgo**: Este método en `data_manager.js` (344-468) es un adapter monolítico que transforma datos de `DataManager` al formato legacy `STATE_DATA`. Contiene lógica de:
- Cálculo de fechas
- Mapeo de columnas
- Filtrado de datos

Todo en una sola función de 125 líneas.

**🏗️ Principio**: Single Responsibility / Function Length

**📍 Ubicación**: `js/data_manager.js:344-468`

dispatchLegacyEvents() {

**📈 Beneficio**: Testabilidad, legibilidad.

## ⚡ PERFORMANCE & DOM

### CQ-006: DOM Queries Repetidas en Loops
**💡 Hallazgo**: Múltiples vistas ejecutan `document.getElementById()` dentro de loops de renderizado o cálculos iterativos, sin cachear la referencia.

**🏗️ Principio**: Layout Thrashing / DOM Access Optimization

**📍 Ubicación**: Patrón generalizado en `vistas2/`.

**Ejemplo** (`vista16.html`):
```javascript
// Cada llamada fuerza un lookup en el DOM tree
document.getElementById('v16_rank_nac').textContent = ...;
document.getElementById('v16_total_nac').textContent = ...;
document.getElementById('v16_rank_clus').textContent = ...;
// ... 6 más
```

**🛠️ Refactor Sugerido**:
```javascript
const els = {
    rankNac: document.getElementById('v16_rank_nac'),
    totalNac: document.getElementById('v16_total_nac'),
    rankClus: document.getElementById('v16_rank_clus'),
};
els.rankNac.textContent = ...;
```

**📈 Beneficio**: Performance (menor overhead DOM), null-safety centralizada.

### CQ-007: `destroyAllCharts()` — Iteración Reversa sobre Chart Instances
**💡 Hallazgo**: `App.destroyAllCharts()` itera sobre `Chart.instances` (un objeto) y destruye cada instancia. El método es correcto pero podría causar problemas si se llama durante un render cycle de Chart.js (ej: durante animación).

**🏗️ Principio**: Thread Safety / Animation Frame

**📍 Ubicación**: `js/app.js:331-347`

**🛠️ Refactor Sugerido**: Envolver en `requestAnimationFrame` para asegurar que no se interrumpe un frame de renderizado.

**📈 Beneficio**: Estabilidad visual durante transiciones.

---

### CQ-008: Chart.js Re-instanciación sin Reutilización
**💡 Hallazgo**: Cada vez que se navega a una vista, se crea una nueva instancia de `Chart`. Aunque `destroyAllCharts()` limpia las anteriores, el patrón destroy+create es menos eficiente que `chart.update()` para vistas revisitadas.

**🏗️ Principio**: Object Pooling / Performance

**📍 Ubicación**: Todas las vistas con gráficos.

**⚠️ Nota**: El refactor sería de alto esfuerzo. Marcar como P3.

**📈 Beneficio**: Transiciones más rápidas al revisitar vistas.

---

### CQ-009: `innerHTML` con Template Literals Extensos
**💡 Hallazgo**: Varias vistas construyen HTML de listados/tablas usando template literals y `.innerHTML`. Esto fuerza al parser HTML a re-procesar todo el subtree. Para listas largas (>20 items), `document.createDocumentFragment()` sería más eficiente.

**🏗️ Principio**: DOM Manipulation / Reflow

**📍 Ubicación**: `vistas2/vista3.html:197`, `vistas2/vista5.html:168`, `vistas2/vista8.html:167`

**📈 Beneficio**: Performance en vistas con tablas grandes.

## 📝 NAMING Y CONSISTENCIA

**💡 Hallazgo**: Ambos arrays coexisten en `STATE_DATA`. `allDataHistory` contiene datos por delito, mientras que `allDataHistory_total` contiene solo la fila "Total". La convención de naming es confusa: `_total` sugiere un sumatorio, no un filtro.

**📍 Ubicación**: `js/data.js:10-11`

### CQ-014: Mezcla CamelCase / snake_case en Columnas
**💡 Hallazgo**: `COLS` mezcla ambas convenciones: `CASOS_ACTUAL` (SCREAMING_SNAKE) para las keys JS, pero los values mapeados usan `snake_case` (`casos_semana_actual`), `camelCase` (`tipoVal`), y `PascalCase` (`Provincia`). Esto proviene del backend Python pero se propaga al frontend.

**📍 Ubicación**: `js/data.js:24-174`

**📈 Nota**: No refactorizar sin actualizar `proceso.py` simultáneamente.

---

### CQ-015: Inconsistencia en Versioning de Scripts (`?v=X`)
**💡 Hallazgo**: Los scripts usan versioning manual por query string (`?v=1`, `?v=2`, `?v=5`). Fácil de olvidar al hacer cambios, causando cache stale en producción.

**📍 Ubicación**: `index_vistas2.html:103-124`

**🛠️ Refactor Sugerido**: Usar un timestamp o hash de build automatizado.
