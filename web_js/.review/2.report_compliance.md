# 🛡️ Reporte de Compliance: compliance-reviewer

## 📋 Contexto
Análisis de seguridad y cumplimiento normativo basado en `.review/0.context_master.md`.

## 🚨 Hallazgos de Seguridad

### 1. Hardcoded Credentials / Obfuscation (Security by Obscurity)
**❗ Hallazgo**: Las claves de API para el servicio de IA (`GLM-4` en `js/ia2.js` y `js/ia.js`) están ofuscadas en el cliente (`getKey` routine). Esto **NO** es seguro. Cualquier usuario con conocimientos básicos de DevTools puede obtener la clave real ejecutando `IAModuleV2.getKey(...)`.
**🔓 Vulnerabilidad**: **Secret Exposure**. Exposición de credenciales de API pagas.
**📍 Ubicación**: `js/ia2.js` (Línea 13), `js/ia.js`.
**⚠️ Severidad**: **Crítica**.
**📜 Estándar**: OWASP Top 10 (A07:2021 – Identification and Authentication Failures).
**🛠️ Mitigación**:
- **Inmediata**: Rotar claves si se sospecha compromiso.
- **Definitiva**: Implementar un **Proxy Server** ligero (Node.js/Python/Cloud Function) que maneje la petición a la API. El cliente solo debe llamar a este proxy sin exponer la clave real.

### 2. Supply Chain: Falta de Integridad en Recursos Externos (SRI)
**❗ Hallazgo**: Se cargan scripts críticos (`Chart.js`, `jspdf`, `FontAwesome`) desde CDNs (`cdn.jsdelivr.net`, `cdnjs.cloudflare.com`) sin atributos de integridad (`integrity="sha384-..."` y `crossorigin="anonymous"`).
**🔓 Vulnerabilidad**: **Supply Chain Attack**. Si el CDN es comprometido, pueden inyectar código malicioso en la aplicación.
**📍 Ubicación**: `index_vistas2.html` (Líneas 58-62, 18).
**⚠️ Severidad**: **Media**.
**📜 Estándar**: PCI-DSS 4.0 (Client-side security).
**🛠️ Mitigación**: Generar hashes SRI para todas las librerías externas o servirlas localmente desde `vendor/`.

### 3. Uso de `innerHTML` en Vistas
**❗ Hallazgo**: Varios elementos KPI actualizan su contenido usando `.innerHTML` con datos que, aunque provienen de fuentes internas (`STATE_DATA`), no pasan por una limpieza explícita.
- Ejemplo: `vDelta.innerHTML = ...` en `vistas2/vista1.html`.
**🔓 Vulnerabilidad**: **DOM-based XSS** (Riesgo bajo si la fuente es confiable, pero riesgo latente si los datos CSV/Excel inyectan scripts).
**📍 Ubicación**: `vistas2/*.html` (Múltiples archivos).
**⚠️ Severidad**: **Baja** (Contexto actual), **Alta** (Si se abre a input externo).
**📜 Estándar**: OWASP Top 10 (A03:2021 – Injection).
**🛠️ Mitigación**: Usar `.textContent` siempre que sea posible. Si se requiere HTML (flechas, colores), usar manipulación de nodos (`createElement`, `classList`) o sanitizar con una librería como `DOMPurify`.

### 4. Exposición de Datos (LocalStorage)
**❗ Hallazgo**: El módulo IA (`js/ia2.js`) guarda análisis completos en `localStorage` sin encriptación.
**🔓 Vulnerabilidad**: **Insecure Storage**. Si el equipo es compartido, otros usuarios podrían leer análisis sensibles si no se limpia el storage.
**📍 Ubicación**: `js/ia2.js` (`saveCache`).
**⚠️ Severidad**: **Baja** (Información pública/estadística), **Media** (Si incluye PII o datos sensibles).
**📜 Estándar**: GDPR (Privacy by Design).
**🛠️ Mitigación**: Evaluar si el caché debe ser `sessionStorage` (se borra al cerrar tab) en lugar de `localStorage`, o implementar expiración estricta y limpieza al logout.

## 📉 Recomendaciones Generales
1.  **Proxy para API Externa**: Urgente. No exponer llaves en JS cliente.
2.  **Audit Dependencias**: Verificar licencias y versiones de librerías CDN.
3.  **Content Security Policy (CSP)**: Implementar headers CSP estrictos para prevenir ejecución de scripts no autorizados.
