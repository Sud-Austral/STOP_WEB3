## 🔴 CRÍTICA

### SEC-001: API Key Expuesta en Código Cliente (Ofuscación Reversible)
**❗ Hallazgo**: La API Key de BigModel (GLM-4) está ofuscada con XOR usando un seed hardcodeado. La ofuscación es trivialmente reversible con cualquier decompilador o incluso inspección manual de DevTools.

**🔓 Vulnerabilidad**: Secret Exposure / Credential Leak

**📍 Ubicación**:
- `js/ia.js:16-25` — `getKey()` con seed `"gfhrsdfsdfseweretfghtddfdf"` y blob base64.
- `js/ia2.js:12-20` — Misma implementación duplicada.
- `js/ia.js:45` — `this.API_KEY = this.getKey("gfhrsdfsdfseweretfghtddfdf");`
- `js/ia2.js:195` — `const API_KEY = this.getKey("gfhrsdfsdfseweretfghtddfdf");`

**⚠️ Severidad**: **Crítica**

**📜 Estándar**: OWASP A01:2021 (Broken Access Control) · CWE-798 (Hard-coded Credentials)

**🛠️ Mitigación**:
1. **Inmediata**: Mover la llamada a la API detrás de un proxy server-side (ej: Cloudflare Worker, Vercel Edge Function).
2. **Mínima**: Implementar un endpoint backend (`/api/interpret`) que tenga la key en variable de entorno y haga la llamada a BigModel.
3. **Rotación**: Rotar la API Key actual ya que debe considerarse comprometida.

```
Cliente → /api/interpret (POST, body: context)
    → Server: env.BIGMODEL_API_KEY → BigModel API
    ← response → Cliente
```

## 🟠 ALTAS

### SEC-002: CDNs sin Subresource Integrity (SRI)
**❗ Hallazgo**: Las 6 dependencias externas cargadas desde CDN no incluyen atributos `integrity` (SRI). Un compromiso del CDN (supply chain attack) permitiría inyectar código malicioso.

**🔓 Vulnerabilidad**: Supply Chain Attack

**📍 Ubicación**: `index_vistas2.html:96-100`
```html
<script src="https://cdn.jsdelivr.net/npm/chart.js" defer></script>
<script src="https://cdn.jsdelivr.net/npm/chartjs-plugin-datalabels@2" defer></script>
<script src="https://cdn.jsdelivr.net/npm/chartjs-plugin-annotation@3" defer></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/html2canvas/1.4.1/html2canvas.min.js" defer></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/jspdf/2.5.1/jspdf.umd.min.js" defer></script>
```
También: `index_vistas2.html:21` (Font Awesome CSS)

**⚠️ Severidad**: **Alta**

**📜 Estándar**: OWASP A08:2021 (Software and Data Integrity Failures)

**🛠️ Mitigación**:
```html
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.7/dist/chart.umd.min.js"
        integrity="sha384-XXXXXX"
        crossorigin="anonymous" defer></script>
```
1. Fijar versiones exactas (no `@latest`).
2. Generar hashes SRI con `shasum` o https://www.srihash.org/.
3. Añadir `crossorigin="anonymous"` a cada tag.

### SEC-003: `innerHTML` con Datos Externos — Riesgo de DOM XSS
**❗ Hallazgo**: Se detectaron **80+ usos** de `.innerHTML` en vistas y módulos core. Aunque actualmente los datos provienen de JSON estático (no de input de usuario), varios flujos incorporan datos de la URL (`codcom`) y de APIs externas (respuestas IA). Si alguno de estos datos contiene HTML, se ejecutaría como código.

**🔓 Vulnerabilidad**: DOM-based XSS (Reflected)

**📍 Ubicación** (ejemplos de mayor riesgo):
- `js/app.js:180` — `container.innerHTML = html` (HTML de fetch, controlado internamente).
- `js/ia2.js:236` — `el.innerHTML = '...'` (string estático, bajo riesgo).
- `vistas2/vista16.html` — `renderList()` inyecta `c.Comuna` en HTML sin sanitizar.
- `vistas2/vista3.html:197` — `tbody.innerHTML` con datos de `allDataHistory`.

**⚠️ Severidad**: **Alta** (el riesgo actual es teórico pero la superficie es amplia)

**📜 Estándar**: OWASP A03:2021 (Injection) · CWE-79

**🛠️ Mitigación**:
1. Para datos dinámicos: usar `textContent` en lugar de `innerHTML` donde sea posible.
2. Implementar una función `sanitize(str)`:
```javascript
function sanitize(str) {
    const div = document.createElement('div');
    div.textContent = str;
    return div.innerHTML;
}
```
3. Auditar los 80 usos y clasificarlos (estático vs dinámico).

### SEC-004: Versiones no Fijadas en CDN (`@latest` implícito)
**❗ Hallazgo**: `chart.js` se carga sin versión fijada (`https://cdn.jsdelivr.net/npm/chart.js`), lo que equivale a `@latest`. Un release malicioso o breaking change se propagaría automáticamente.

**🔓 Vulnerabilidad**: Supply Chain — Dependency Confusion

**📍 Ubicación**: `index_vistas2.html:96`

**⚠️ Severidad**: **Alta**

**📜 Estándar**: OWASP A06:2021 (Vulnerable and Outdated Components)

**🛠️ Mitigación**: Fijar a versión exacta: `chart.js@4.4.7`

## 🟡 MEDIAS

### SEC-005: Datos Policiales en localStorage sin Cifrar
**❗ Hallazgo**: Las interpretaciones de IA (que contienen análisis de datos policiales sensibles) se almacenan en `localStorage` en texto plano. Cualquier extensión del navegador o script de terceros puede leerlas.

**🔓 Vulnerabilidad**: Data Leak / Sensitive Data Exposure

**📍 Ubicación**: `js/ia.js:87-98` (`saveToCache`)

**⚠️ Severidad**: **Media** (datos agregados, no PII directa)

**📜 Estándar**: GDPR Art. 32 (Data Protection by Design)

**🛠️ Mitigación**: 
- Cifrar con `SubtleCrypto` API antes de guardar.
- O migrar a `sessionStorage` (más efímero).

### SEC-006: URL Parameter `codcom` sin Validación
**❗ Hallazgo**: El parámetro `codcom` de la URL se parsea con `parseInt()` sin validación de rango o formato. Aunque `parseInt` mitiga inyección de strings, no valida que el código comunal sea legítimo.

**🔓 Vulnerabilidad**: Input Validation

**📍 Ubicación**: `js/data_manager.js:72`

**⚠️ Severidad**: **Media**

**📜 Estándar**: OWASP A03:2021 (Injection)

**🛠️ Mitigación**:
```javascript
const raw = parseInt(params.get('codcom'));
const codcom = (raw >= 1101 && raw <= 16305) ? raw : this.config.defaultComuna;
```

### SEC-007: Requests a Dominio Externo (BigModel China)
**❗ Hallazgo**: La aplicación hace requests directos desde el navegador del usuario a `https://open.bigmodel.cn` (API de IA en China). Esto implica:
1. Datos policiales chilenos enviados a servidores en China.
2. Sin Content Security Policy (CSP) Header configurado.

**🔓 Vulnerabilidad**: Data Exfiltration / Regulatory Risk

**📍 Ubicación**: `js/ia.js:29`, `js/ia2.js:9`

**⚠️ Severidad**: **Media** (riesgo regulatorio más que técnico)

**📜 Estándar**: GDPR / Ley 19.628 (Chile) sobre transferencia internacional de datos

**🛠️ Mitigación**: Proxy server-side en infraestructura nacional. Esto también resuelve SEC-001.

## 🟢 BAJAS

### SEC-008: Sin Content Security Policy (CSP)
**❗ Hallazgo**: No se detecta ningún meta tag `<meta http-equiv="Content-Security-Policy">` ni Header CSP. Esto permite la ejecución de cualquier script inline y la carga de recursos de cualquier origen.

**📍 Ubicación**: `index_vistas2.html` (ausencia)

**⚠️ Severidad**: **Baja** (la app depende de scripts inline, implementar CSP requiere refactorización)

**📜 Estándar**: OWASP A05:2021 (Security Misconfiguration)

---

### SEC-009: `console.log` Expone Estructura Interna
**❗ Hallazgo**: Mensajes de debug (`console.log`, `console.warn`) revelan nombres de módulos, rutas de datos, y estructura de cache en la consola del navegador.

**📍 Ubicación**: Múltiples archivos (20+ instancias).

**⚠️ Severidad**: **Baja** — Facilita reconnaissance pero no es explotable directamente.

**🛠️ Mitigación**: Implementar un logger condicional: `const log = (PROD ? () => {} : console.log.bind(console));`
