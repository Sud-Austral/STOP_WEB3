# 🏗️ REPORTE DE ARQUITECTURA (Native Design Patterns)

**🏗️ Aspecto**: `DataManager` como God Object.
**📐 Patrón Detectado**: Singleton / God Object.
**⚠️ Riesgo Arquitectónico**: Acoplamiento extremo. `DataManager` gestiona configuración, carga, descompresión, procesamiento de datos de dos fuentes distintas, hidratación de estados legacy y despacho de eventos. 
**📈 Recomendación**: Descomponer en servicios especializados: `DataFetcher` (red/descompresión), `MappingService` (taxonomía/COLS) e `IdentityManager` (comuna/región).

---

**🏗️ Aspecto**: Comunicación entre Componentes (Vistas).
**📐 Patrón Detectado**: Custom Events (Observador).
**⚠️ Riesgo Arquitectónico**: Fragilidad. La arquitectura MPA (Multi-Page App) hace que cada vista deba "esperar" manualmente al `DataManager` local. Si el evento se dispara antes de que la vista termine de parsearse, la ejecución se bloquea.
**📈 Recomendación**: Implementar un sistema de *State Observables* que permita a las vistas suscribirse al estado independientemente del momento de carga.

---

**🏗️ Aspecto**: Capa de Presentación (Vistas HTML).
**📐 Patrón Detectado**: Script Injection / Inline Logic.
**⚠️ Riesgo Arquitectónico**: Falta de escalabilidad. La lógica de negocio está fuertemente incrustada en el HTML (`vistaX.html`).
**📈 Recomendación**: Extraer la lógica de renderizado específica a controladores JS externos y utilizar el HTML únicamente como plantilla declarativa.
