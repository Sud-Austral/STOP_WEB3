# 🏗️ Reporte de Arquitectura (Agente: architecture-reviewer)

## 📋 Resumen
Evaluación de la estructura SPA y el patrón de consumo de estado.

## 🏗️ Evaluación Estructural

**🏗️ Aspecto**: Arquitectura de Gestión de Estado (Singleton)
**📐 Patrón Detectado**: Global Object State (`window.STATE_DATA`)
**⚠️ Riesgo Arquitectónico**: Alto Acoplamiento / Fragilidad ante Cambios
**📈 Recomendación**: Evolucionar `STATE_DATA` hacia un **View Model** (o Repository Pattern). Instead of accessing `S.allDataHistory_total`, expose methods like `DataManager.getRecentTrends(8)` or `DataManager.calculateZScore(weekId)`.
**📉 Impacto Actual**: Cada cambio en el formato del JSON obliga a revisar/reescribir 30+ vistas.

**🏗️ Aspecto**: Navegación y Enrutamiento (SPA Shell)
**📐 Patrón Detectado**: `fetch` HTML Injection (`App.loadView`)
**⚠️ Riesgo Arquitectónico**: Riesgo de "Zombie Listeners" (Memory Leaks)
**📈 Recomendación**: Implementar un **Router** real que maneje el ciclo de vida de las vistas (`mount`/`unmount`). Las vistas deberían exportar una función `cleanup()` para liberar recursos (Chart.js instances, intervals).
**📉 Impacto Actual**: Navegación rápida puede dejar gráficos invisibles consumiendo memoria.

**🏗️ Aspecto**: Inyección de Dependencias (IA/Data)
**📐 Patrón Detectado**: Hard Dependency (`IAModule`, `DataManager` globales)
**⚠️ Riesgo Arquitectónico**: Dificultad para Testear / Mckear
**📈 Recomendación**: Pasar las dependencias como argumentos a la función de inicialización de la vista (`initVista1(DataManager, IAModule)`).
**📉 Impacto Actual**: Imposible probar una vista aislada sin cargar todo el entorno global.

**🏗️ Aspecto**: Escalabilidad de Vistas
**📐 Patrón Detectado**: Archivos Individuales con Lógica Incrustada (`<script>` inside HTML)
**⚠️ Riesgo Arquitectónico**: Dificultad de Mantenimiento / Linting
**📈 Recomendación**: Separar la lógica JS en archivos `.js` adjuntos (`vistas2/js/vista1.js`) y cargarlos dinámicamente. Esto permite linting, minificación y mejor organización.
**📉 Impacto Actual**: Lógica dispersa entre HTML y blocks `<script>`.

## 📉 Conclusión
La arquitectura actual es funcional para un Dashboard estático/semi-estático pero presenta riesgos de mantenibilidad a medida que crece el número de vistas y la complejidad de la lógica de negocio. Se recomienda priorizar la **centralización de la lógica de negocio** (sacarla de las vistas) y **robustecer el ciclo de vida de las vistas**.
